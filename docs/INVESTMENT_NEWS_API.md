# Public investment news

The additive `GET /api/intelligence/news` endpoint reads `static/data/intelligence_investment_news.json` through the existing `published_data` reader. `GET /api/published-data/intelligence_investment_news.json` exposes the same validated projection. Both preserve the actual publication timestamp and use `Cache-Control: no-store, max-age=0, must-revalidate` with `X-ChartView-Data-Source` and `X-ChartView-Data-AsOf`.

The canonical envelope is `schemaVersion: investment-news.v1`, UTC `generated_at`, KST `as_of_date`, `status` (`READY`, `PARTIAL`, `NOT_STARTED`), `collection`, `capabilities`, `events`, and `briefings`. The checked-in seed is explicitly empty and `NOT_STARTED`. It does not establish a running collector, configured model, delivered Telegram message, or observed return.

The API validates the bounded public projection and serves no private repository, database, thesis text, holdings, raw Telegram content, full article body, model prompt, or raw audit. Telegram source URLs and enabled Telegram-input capabilities are refused. Unknown producer metadata is omitted; sensitive key names and private-looking prose fail closed before projection. Facts must cite an event source URL. All events and briefings retain `trade_action: REVIEW_ONLY`; the existing audited PICK feed, BUY/WAIT/SELL decisions, scores, histories, and performance ledgers are untouched.

Optional analysis fields can be absent without fabricating results. `completed` requires actual mer/nonggu/meng result objects, summaries, and evidence identifiers. Capability values are booleans describing configuration, not successful execution; both `telegram_input` and `telegram_input_enabled`, when present, must be false. Numeric returns use the canonical fractional `stock_return`, `benchmark_return`, and `excess_return` fields and require finite numbers, baseline/followup timestamps in order, and public `source_urls`; missing returns remain null or absent. Unsupported percentage aliases (`return_pct`, `benchmark_return_pct`, `excess_return_pct`, `mdd_pct`) are refused. Scalar performance source URLs and thesis-review evidence URLs receive the same HTTPS/privacy checks as event sources. `as_of_date` must equal the KST calendar date of the actual UTC `generated_at`. Upstream evidence remains the producer's responsibility: this read API does not run models or fetch/verify article or price sources.

Collection metadata includes actual source success/failure timestamps, counts, and sanitized error classes. Historical briefings may reference valid event identifiers outside the current 300-event retention window, because the producer retains up to 90 daily briefings. Such references do not synthesize an event or change an existing analysis.

The existing reader checks GitHub main with a short bounded cache and retains newer validated data if remote publication is invalid, unavailable, or older. It falls back to the dated deployment seed when no newer valid publication exists. A source collection failure is distinct from the publication reader failing. The convenience news route responds with a generic 503 on invalid/unavailable publication rather than leaking local file paths or raw exception details.

Publishing an actual sanitized snapshot and deploying the exact tested backend revision are coordinator tasks. Local API tests and checked-in configuration are not evidence of a continuously running worker, live AI, notifications, native Toss validation, or a deployed release.

Local validation on 2026-10-21: the full Python suite passed 1,173 tests and 43 subtests, existing Node contracts passed 52 tests, and frontend bundle freshness passed. The actual six-source, 122-event official-feed snapshot also passed the projector and a standalone local FastAPI response check. Its publication time was `2026-10-21T23:26:32.627596+00:00`; the actual feed was not committed in this change. Expected pre-existing deprecation warnings were retained. Remote CI, exact Render deployment, producer runtime, and native validation remain unverified here.
